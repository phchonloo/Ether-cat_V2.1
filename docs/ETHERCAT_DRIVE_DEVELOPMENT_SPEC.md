## 0. 如何使用本文档

本文把“能转动的样机”到“可交付驱动器”之间需要完成的工作列成可以开发、复核和测试的要求。完整产品不是支持尽可能多的模式，而是对声明的每一项功能都有正确实现、明确边界、异常行为和验收证据。

2026-10-12 更新：SQI/PDI 事务失败传播、PDO 发布保护及首错记录已完成代码修正和离线验证，实板异常注入与随机停转根因仍待闭环。实现边界、诊断字段和验证方法见 [MCU 通信修正与测试说明](MCU_PDI_COMMUNICATION_FIX_AND_TEST.md)。

阅读顺序：负责人先看第 1～4 章与第 22～24 章；固件开发看第 5～17 章；硬件和测试看第 18～21 章；PLC 集成看第 10～12 章和第 17 章。

要求用语：

- **必须（M）**：本产品选定范围内的发布要求；不一定等同于某个外部标准的强制条款。
- **建议（R）**：改善兼容性、维护性或产品竞争力，是否纳入本版应书面决定。
- **可选（O）**：仅在产品声明该能力后成为必须开发和验收的要求。
- **P0**：当前可靠性、保护或一致性阻断项，应优先解决。
- **P1**：本版产品选定功能和量产准备。
- **P2**：扩展能力与后续型号。
- **已见实现**：检查到源码或配置，不代表经过完整实机验证。
- **待验证**：缺少对应版本、硬件和工况的可复核结果。
- **待实现／未启用**：本次检查未见完整路径，或配置明确关闭。

不得用本文件中的复选框数量计算“完成百分比”。一个失控风险或错误停机语义未关闭，可能比几十个普通功能未完成更重要。

## 1. 产品边界与必须冻结的规格

### 1.1 本版建议定位

第一版定位为“单轴、开环步进、支持 CoE/CiA402 的 EtherCAT 驱动器”。优先完成 PP、PV、CSP、CSV 的可靠实现；将真实停止动作、通信丢失处理、参数持久化、诊断和产品测试作为基本能力。HM 是否纳入首版由用途决定，若用于需要上电找机械原点的定位设备，建议纳入首版。

以下能力不能仅靠修改 XML 或添加对象名称获得：闭环伺服、真实机械跟随误差、转矩控制、绝对位置恢复、STO、安全限速、安全通信、断电保持位置。

CiA402 规定了状态机、操作模式和参数，但包含不同适用范围与可选功能。必须选择并记录所采用的规范版本及 EtherCAT 映射要求，不能把“有 0x6040/0x6041”当作完整符合性证明。[CiA 官方概述](https://www.can-cia.org/can-knowledge/cia-402-series-canopen-device-profile-for-drives-and-motion-control)

### 2.3 已知问题必须留在问题单中

1. 运行中曾发生自动停转，PLC 首错记录 nStopReason=1、diagWcState=TRUE；这证明 PLC 观察到过程数据无效并触发锁存，不证明是哪一侧导致异常。
2. 后续部分 INIT NO_COMM、丢帧增加的截图包含人工停止／重启操作，不能直接用作原始停机根因证据。
3. 观察到 OP 正常或 WcState 恢复为 0，不能推翻此前的异常；累计计数包含启动和非运行阶段，不能当作运行中丢帧次数。
4. 该问题在获得无人工干预的首错记录、根因复现、修复和长期回归前保持“未关闭”。
5. GitHub 连接失败属于开发环境问题，不能与 EtherCAT 实时通信错误混为一谈。

## 5. 软件架构与模块职责规范

### 5.1 推荐分层

~~~text
主站／PLC／NC（每轴一个命令拥有者）
        ↓ PDO／SDO
EtherCAT 栈与对象字典适配
        ↓ 验证、单位转换、原子提交

诊断、故障、非易失存储（与实时路径解耦）
~~~

| N32G455.lib | 已知边界内的电机算法 | 成为无法版本追踪、无法验证的黑箱依赖 |

### 5.3 命令所有权

- ARCH-01（M）：每个轴同一时间只有一个运动命令源。EtherCAT、Modbus、调试串口、面板必须经同一仲裁层切换。
- ARCH-02（M）：NC 已链接的输出不能再由 PLC 直接写同一个 PDO 地址；双重映射应在集成阶段拒绝。
- ARCH-03（M）：参数写入、动作请求、诊断读取分离；读取状态不能改变运动。
- ARCH-04（M）：命令包含模式、目标、限幅、序号、有效性和接收时间，作为一个整体提交。
- ARCH-05（M）：状态机拥有状态，运动层拥有执行状态，采样／计数层拥有反馈；通过接口交换，不跨层随意写全局变量。
- ARCH-06（M）：电机库固定版本、文件哈希、许可、支持的调用上下文、输入尺度和异常条件必须记录。

## 6. C／H 代码规范

### 6.1 工具链与代码风格

- CODE-01（M）：锁定 MCU 型号、SDK、SSC、编译器、优化等级、链接脚本、宏和库版本。当前工程采用 Keil/ARMCC 路径，不默认支持所有 C11 特性。
- CODE-02（M）：新代码使用编译器明确支持的 C 子集。禁止依赖未定义行为、隐式函数声明、未初始化变量或未审查的实现相关行为。
- CODE-03（M）：新增代码编译零警告。历史警告建立清单、责任人与关闭计划；不得整体关闭警告以满足指标。
- CODE-04（R）：新文件 UTF-8、四空格缩进、统一大括号风格，建议行宽不超过 100～120 字符。老文件编码转换应单独提交，防止中文注释损坏与大面积无关差异。
- CODE-05（M）：一个文件一类职责；公共头文件有 include guard，可独立包含；不得在头文件定义普通可变全局对象。
- CODE-06（M）：头文件声明 API、单位、调用上下文、失败返回值、阻塞上限和线程／中断约束；内部函数与变量使用 static。
- CODE-07（R）：新接口使用模块前缀，例如 Motor_StopRequest、Param_SaveRequest、Esc_Read；不为命名美观批量改动协议栈或库 ABI。
- CODE-08（M）：固定宽度数据用于通信和持久化。旧 u8/s32 等别名应确认宽度，不能凭 int/long 在不同编译器下的大小推断协议布局。

### 6.2 单位、数值与范围

- CODE-09（M）：变量名或注释标明单位，如 cycle_time_ns、target_velocity_rpm、accel_rpm_s、position_counts。内部 BaseRpm 比例只能通过集中换算进入接口。
- CODE-10（M）：乘法先扩展到足够宽的类型，再计算并检查范围；有符号溢出不是合法的回绕策略。
- CODE-11（M）：明确负数除法、舍入、余数累计、INT32_MIN 取绝对值以及跨零换向的行为。
- CODE-12（M）：不得用浮点数直接做累计位置相等判定；外部 DINT 位置到边界前必须有明确限制策略。
- CODE-13（M）：运行中修改分辨率、齿轮比、坐标基准必须被拒绝，或使用经过验证的停机重建流程；不能只改比例而不改内部状态。
- CODE-14（M）：计数器区分饱和计数和有意回绕的时间戳；时间差算法写明支持的最大间隔，不用简单大小比较跨回绕时间。
- CODE-15（M）：不要把 0、无穷大、负数、NaN 或越界参数默默转换为可运行命令；按接口定义拒绝或显式限幅并报告。

### 6.3 内存、返回值与硬件访问

- CODE-16（M）：运行期实时路径不使用动态分配、递归、printf、格式化字符串或无上界循环。协议栈初始化分配须检查失败；栈自带邮箱资源须做配额与释放审计。
- CODE-17（M）：所有指针、长度、索引、对象子索引和 DMA 缓冲区边界在使用前校验；禁止 count=0 后直接计算 count-1。
- CODE-18（M）：检查硬件操作、分配、转换和协议服务返回值；失败时不得继续发布成功结果。
- CODE-19（M）：超时基于可测量时间或经测量约束的循环次数。循环次数不能在优化、频率改变后仍假定对应相同微秒数。
- CODE-20（M）：寄存器按芯片手册访问；清中断、读清／写一清零寄存器必须记录副作用。
- CODE-21（M）：禁止把任意通信字节缓冲区直接强转为未对齐结构体后解引用。处理大小端、对齐、填充和有效长度。
- CODE-22（M）：返回错误码和更新诊断是两件事；增加 timeout_count 不能代替失败返回。

### 6.4 返回值接口示例（新设计示意，不是现成修复）

~~~c
typedef enum
{
    ESC_IO_OK = 0,
    ESC_IO_INVALID_ARGUMENT,
    ESC_IO_TIMEOUT,
    ESC_IO_BUS_ERROR
} EscIoResult;

/* 不得在电机 ISR 调用。调用者只在返回 OK 时使用整个目标缓冲区。

EscIoResult Esc_Read(uint16_t address, uint8_t *buffer, uint16_t size);
~~~

### 6.5 注释、评审与变更

- 注释解释原因、单位、时序和边界；不要复制一段已过期的功能承诺。
- 所有新增对象／宏记录用途、默认值、范围、持久化和版本影响。
- TODO 必须附问题编号和失败后果，保护关键路径不能带着无期限 TODO 发布。
- 修改协议栈要保留来源／许可头、基线版本、补丁原因与回归用例；升级 SSC 时逐项重放补丁。
- 采用 MISRA C／CERT C 风格约束时，应明确所选版本、检查工具和偏离审批；不能只做一次静态扫描便宣称已符合。

## 7. 中断、并发与最坏时序规范

### 7.1 当前时序事实

当前 TIM8 电机环为 16 kHz，周期 62.5 μs；main.c 设置其抢占优先级为 0。主循环依次服务协议 MainLoop、运动更新、Modbus 和 EEPROM 控制台。优先级必须根据硬件保护、实时环截止时间、ESC 访问和邮箱服务预算共同确定，不能规定“协议永远最高”或“电机永远最高”作为通用修复。

### 7.2 必须测量的量

| 编号 | 测量项 | 验收原则 |
| --- | --- | --- |
| RT-01 | 电机 ISR 最坏执行时间与入口延迟 | 最坏执行、阻塞、抢占和入口延迟总和小于 62.5 μs，留经过批准的裕量 |
| RT-02 | PDI／SYNC0 服务延迟与抖动 | 在所有支持周期和邮箱负载下满足 ESC 与应用时序 |
| RT-03 | 关中断／临界段最大时间 | 有实测上限；不能覆盖整个邮箱或 Flash 事务 |
| RT-04 | 主循环最长一圈、邮箱最大等待时间 | 超时和错误重试工况仍有上界 |
| RT-05 | 栈和内存高水位 | 中断嵌套、异常路径和日志高峰都覆盖 |
| RT-06 | PWM／ADC 对齐、电流采样延迟 | 不以 CPU 平均负载替代相位与时序测量 |

测量同时记录 CPU 频率、编译优化、调试开关、库版本、邮箱负载和仪器。平均 CPU 占用低、PLC Exceed Counter=0，均不能单独证明 MCU 最坏时延合格。

### 7.3 并发规则

- RT-07（M）：volatile 不等于互斥、原子快照或内存屏障；32 位 MCU 上的 64 位位置／相位不能默认原子读写。
- RT-08（M）：实时消费者使用已完整发布的快照；可采用经过分析的双缓冲、短临界段或平台支持的原子机制。
- RT-09（M）：高优先级 ISR 不得自旋等待被它打断的低优先级写入者；序列锁读重试必须考虑优先级关系和上界。
- RT-10（M）：所有临界段恢复原中断屏蔽状态，不允许退出时无条件开中断；BASEPRI／PRIMASK 的用法需与内核优先级位数一致。
- RT-11（M）：SQI 访问单一仲裁，禁止主循环和中断交错拼接同一事务；不能通过长时间屏蔽电机 ISR 来获得协议互斥。
- RT-12（M）： ISR 中只记录简短事件和计数；格式化、持久化、上传放在后台，并限制日志速率。
- RT-13（M）：IWDG／WWDG 喂狗应反映关键任务健康；不能让仍运行的一个中断掩盖主循环或协议任务永久卡死。
- RT-14（M）：中断优先级、时钟、编译优化、Flash 操作方式改变时，重做实时性回归。

## 8. EtherCAT 基础与 ESI／SII 规范

### 8.1 协议基本要求

- ECAT-01（M）：INIT、PREOP、SAFEOP、OP 的进入、退出、超时和错误确认正确；应用状态与 AL 状态协同，不以进入 OP 直接使能功率。
- ECAT-02（M）：PREOP 可按声明进行邮箱配置；SAFEOP／退出 OP 后不得继续执行先前运动命令。输出的具体停止行为由风险评估和停止策略决定。
- ECAT-03（M）：SII 身份、ESI 身份、0x1018、在线扫描结果一致；生产序列号唯一且可追溯。
- ECAT-04（M）：SM、FMMU、邮箱及 PDO 地址、尺寸、访问方向与 ESC 可用 RAM 一致；所有被允许的大小组合均不能重叠。
- ECAT-05（M）：状态切换失败时返回真实 AL Status Code，并保留可追踪原因；不得永久忽略错误以维持 OP。
- ECAT-06（M）：ESC Process Data Watchdog、SYNC0 监督、应用命令新鲜度分别测试，不能相互替代。
- ECAT-07（M）：断网、主站停任务、线缆异常、无效映射、非法周期和 MCU 复位时，功率输出行为确定，恢复通信不自动恢复旧动作。
- ECAT-08（M）：恒定目标的有效 PDO 也属于新通信；新鲜度根据收到的有效周期／序号／时间判断，不能根据目标数值是否变化判断。
- ECAT-09（M）：同一周期的 PDO 数据要完整提交；事务失败或校验失败时不把半帧对象当作新目标。
- ECAT-10（M）：ESC 固件／硬件版本差异、PDI 字节序、寄存器副作用和最大事务长度纳入移植清单。

### 8.2 ESI 管理

当前文件为 FCM4E1553_CiA402_SingleAxis_Rev03.xml。文件名服务于版本管理；真正的兼容身份由 Vendor ID、Product Code、Revision 等字段决定。改文件名不会自动改变已经安装的设备定义。

- ESI-01（M）：使用合法分配／授权的 Vendor ID，验证归属；不得复制其他成品的厂商身份或产品代码来模拟兼容。
- ESI-02（M）：先完成固件，再声明功能。HM、FoE、Complete Access、PDO Config 等不能只在 ESI 中设为支持。
- ESI-03（M）：单轴型号可采用扁平 RxPDO／TxPDO 描述；模块化结构只有在真实需要模块／多轴时使用，不能只按主站目录外观判断功能质量。
- ESI-04（M）：对象索引、子索引、数据类型、位宽、访问权限、单位、默认值和 PDO 可映射性与在线 SDO Info 一致。
- ESI-05（M）：固定映射与可配置映射声明分别核对。当前 ESI 同时存在 Fixed PDO 与 PdoConfig/PdoAssign 声明，需按实际可写范围验证，不能仅凭字段组合断定正确或错误。
- ESI-06（M）：DC 模式、AssignActivate、最小周期、SYNC0/1 能力只描述实测支持项；不把宏或 XML 默认值当作性能证明。
- ESI-07（M）：布局或兼容性变化时更新 Revision 与发布说明；保留旧版以支持已交付设备。
- ESI-08（M）：用约定 ESI Schema 校验，并在全新 TwinCAT 工程重新扫描测试，不能只验证已有工程缓存。
- ESI-09（M）：变更必须说明是否需要重新安装 ESI、重新扫描、重新链接 PDO、重新写 SII 或迁移参数；这些动作不是同一件事。

## 9. CoE、邮箱与对象字典规范

### 9.1 邮箱服务

- COE-01（M）：普通上传／下载、声明支持的分段与 Complete Access、SDO Info 列表／对象／条目查询均需测试。
- COE-02（M）：不存在对象／子索引、只读写入、长度不符、范围错误、状态不允许和不支持访问方式返回对应 Abort；不能返回成功但未改变值。
- COE-03（M）：Mailbox 长度、类型、计数器、分段 toggle、重复请求、超时和恢复路径具备边界检查。
- COE-04（M）：邮箱缓冲、发送队列和挂起响应有固定资源上限；满队列行为明确，不得永久锁死或覆盖仍被使用的缓冲。
- COE-05（M）：在电机运行和 DC 同步时批量读对象字典，PDO 截止时间与邮箱最大服务时延同时合格。

| 0x6081／0x6083／0x6084 | 轮廓速度／加速度／减速度 | 已见；单位为当前工程约定，不能套用其他厂家的缩放 |
| 0x6085 | Quick stop deceleration | 已见对象；需接真实停止控制，测试边界与不可用值 |
| 0x608F／0x6091／0x6092 | 位置分辨率／齿轮比／进给常数等缩放 | 按型号与所选接口规划；没有编码器时不得捏造编码器分辨率 |
| 0x6098／0x6099／0x609A | 回零方法／速度／加速度 | HM 功能规划；当前不能宣称支持 |
| 0x60C2 | Interpolation time period | 已见；周期换算与实际同步来源一致，非法组合可识别 |
| 0x60FD | Digital inputs | 有相关硬件及应用需求时实现，明确各位定义／极性／有效性 |
| 0x60FF | Target velocity | 已见；PV／CSV 的生效方式分别说明 |
| 0x6502 | Supported drive modes | 已见；由真实模式集合生成，与 0x6060 和 ESI 一致 |
| 0x206C 等厂商对象 | 厂商错误与扩展诊断 | 当前有错误子码对象；其他扩展应先登记索引，避免冲突 |

新增电流／转矩、探针锁存或多轴对象时，单独补设计卡和测试。不能把另一品牌对象表全部复制后，把缺失值补零当作完成移植。

## 10. PDO 布局与 PLC 集成规范

### 10.1 当前默认布局

方向均以从站为准：RxPDO 是从站接收的控制数据，TxPDO 是从站发出的反馈。下表是当前默认组合的相对字节偏移，不是 TwinCAT 工程的固定绝对地址。

| 方向 | 偏移 | 对象 | 类型 | 字节数 | 含义 |
| --- | ---: | --- | --- | ---: | --- |
| Rx | 0 | 0x6040:0 | UINT16 | 2 | 控制字 |
| Rx | 2 | 0x607A:0 | INT32 | 4 | 目标位置 |
| Rx | 6 | 0x60FF:0 | INT32 | 4 | 目标速度 |
| Rx | 10 | 0x6060:0 | INT8 | 1 | 请求模式 |
| Rx | 11 | Padding | UINT8 | 1 | 填充 |
| Tx | 0 | 0x6041:0 | UINT16 | 2 | 状态字 |
| Tx | 2 | 0x6064:0 | INT32 | 4 | 当前实现的内部计数位置 |
| Tx | 6 | 0x606C:0 | INT32 | 4 | 当前实现的内部相位速度 |
| Tx | 10 | 0x6061:0 | INT8 | 1 | 生效模式 |
| Tx | 11 | Padding | UINT8 | 1 | 填充 |

Rx、Tx 各 12 字节。WcState 和 InfoData.State 属于 TwinCAT 诊断映像，不要误加到这 12 字节从站 PDO 中。

### 10.2 映射与主站规则

- PDO-01（M）：校验总位数、对象是否可映射、方向、子索引、对齐和填充；解析范围不得超过本次有效报文长度。
- PDO-02（M）：动态映射若支持，必须定义合法状态、清零／配置／提交顺序，并在成功后原子切换；运行中不允许半套映射生效。
- PDO-03（M）：同一控制输出不得同时链接 NC、PLC 和其他命令源；映射冲突必须先解决再使能。
- PDO-04（M）：样例明确每个变量的类型、方向和链接对象；模式用 SINT，位置／速度用 DINT，控制／状态字用 UINT。
- PDO-05（M）：PLC 程序声明区与执行区分别提供，不让用户把 IF/CASE 执行语句粘贴到 VAR 声明区。
- PDO-06（M）：运行前校验周期、模式显示、位置缩放、反馈来源、控制字状态、WcState 和从站状态。
- PDO-07（M）：正常操作用 Write values，不使用 Force 覆盖使能、目标、状态和保护变量。
- PDO-08（M）：必须说明 NC Online 置灰、映射冲突、SDO 写后又恢复、驱动 OP 与轴未使能等现象的不同原因，不能统一归因于驱动故障。
- PDO-09（M）：工程示例不得默认上电自启、自动 Fault Reset 或总线恢复后自动重新运动。

## 11. CiA402 状态机与停止语义

### 11.1 基本状态要求

至少覆盖 Not ready to switch on、Switch on disabled、Ready to switch on、Switched on、Operation enabled、Quick stop active、Fault reaction active、Fault 的适用转换。

- DS402-01（M）：控制字按位解释；状态判断使用规定掩码，不拿完整状态字做固定十进制相等比较。
- DS402-02（M）：0x6060 是请求，0x6061 是实际生效模式；不支持的请求必须拒绝或进入明确的非运行结果，不能假装已进入该模式。
- DS402-03（M）：普通使能流程逐步发送 0x0006、0x0007、0x000F，并等待各步正确状态；每步有超时，不是固定延时后无条件继续。
- DS402-04（M）：Fault Reset 只接受定义的边沿／请求；故障条件仍存在时不得清除，复位后不自动恢复上一次运动。
- DS402-05（M）：AL OP 与 Operation enabled 分开管理；仅 OP 不代表电机可运行，仅收到使能命令也不代表输出已安全开启。
- DS402-06（M）：状态字中的 Ready、Fault、Warning、Target reached、Internal limit 和模式专用位对应真实条件。
- DS402-07（M）：状态字 bit12、bit13 等按当前模式解释，不跨模式沿用；PP 的 set-point acknowledge 不等同于 CSP 的跟随命令标志。

### 11.2 停止方式必须分别实现

| 停止类型 | 产品必须定义的行为 | 验收重点 |
| --- | --- | --- |
| 普通循环结束 | 完成当前动作或按规定结束，是否保持励磁明确 | 不多走一圈，不误清零坐标 |
| Halt | 按模式及选项进入规定的暂停／减速行为 | 取消 Halt 后的继续／重新启动规则 |
| Disable operation | 执行选定停止行为并转换状态 | 状态不能先报告完成再实际减速 |
| Shutdown／Disable voltage | 按规范和硬件能力撤销驱动 | 电流、保持力和垂直负载后果 |
| Quick stop | 按 0x605A 和相关减速设置停止 | 可测停止轨迹、完成判据与后续状态 |
| Fault reaction | 根据故障严重度减速或立即关断 | 不可在严重过流时等待普通减速完成 |
| 通信失效 | 使用本地预定策略，不依赖下一帧控制字到来 | 失联后仍能在批准时限内作出反应 |
| 硬件保护关断 | 由经过设计验证的硬件链处理危险故障 | 与 MCU 是否卡死、网络是否正常无关 |

当前 TransitionAction 的“反馈置零、立即返回 TRUE”只能算占位路径。必须接入停止请求、执行中、停止完成／失败三阶段，并防止运动层因状态先改变而过早撤销必要减速动作。

减速完成的证据根据产品反馈能力定义。开环相位速度降为零只能证明命令／励磁推进停止，不能证明机械轴已停稳；有垂直负载、惯性或制动器的应用需额外策略与测量。

普通控制字停机、函数名中的 EmergencyStop、PWM 关闭均不得被宣传为 STO。人员安全不能只依赖这份 PLC 示例或单一软件变量。

## 12. 运动模式的详细功能与验收要求

### 12.1 共用要求

- MOT-01（M）：使能时目标与当前坐标对齐，或使用明确的第一目标接受流程，防止继承旧目标突然跳转。
- MOT-02（M）：模式切换期间命令与轨迹状态重新初始化；首版建议失能、停止后切换。若支持带速切换，须另有平滑与一致性验证。
- MOT-03（M）：正负方向、零点、软件限位、机械限位和分辨率定义统一；不得让对象字典单位与 PLC 单位各自解释。
- MOT-04（M）：所有模式都有速度、电流、加速度及位置有效范围控制；限幅不应静默伪装成完全跟随。
- MOT-05（M）：目标不变、速度为零、跨零、正反转、边界位置、异常周期和连续重复命令都需测试。
- MOT-06（M）：内部计数到位、控制误差到位和机械到位分开定义；无传感器时不能虚报真实机械跟随误差保护。

### 12.2 PP：Profile Position，模式 1

PP 由驱动器根据目标位置与轮廓参数生成运动。必须支持本版声明的绝对／相对定位、目标握手、加减速、到位、暂停、停止及软件限位行为。

当前用户采用的十进制流程应在说明书中同时写出十六进制和条件：

| 控制字十进制 | 十六进制 | 用途 |
| ---: | --- | --- |
| 6 | 0x0006 | Shutdown，等待 Ready to switch on |
| 7 | 0x0007 | Switch on，等待 Switched on |
| 15 | 0x000F | Enable operation，等待 Operation enabled |
| 47 | 0x002F | 在该 PP 用法中将 new set-point 位清零，准备握手 |
| 63 | 0x003F | new set-point 位产生上升沿，请求接受新目标 |

这不是所有模式的通用控制流程。绝对／相对、立即切换等位改变时数值也会改变；启动第二个目标前必须完成规定的握手与重新置位过程。

- PP-01（M）：写入目标和参数后，再发 new set-point 上升沿；目标快照一次锁定。
- PP-02（M）：持续保持触发位不会每周期重新接受目标；重复相对命令不能被误执行多次。
- PP-03（M）：set-point acknowledge、target reached、following error 等位按选定规范和实际能力实现。
- PP-04（M）：0x6081／0x6083／0x6084 与可支持的轮廓行为一致；改变参数时明确当前动作还是下一动作生效。
- PP-05（M）：定义运行中追加目标、立即改变目标和缓冲能力；不支持队列时明确拒绝或按文档规则处理。
- PP-06（M）：达到端点后不因速度残量继续推进，也不能通过错误反向补偿掩盖端点规划问题。
- PP-07（M）：绝对／相对、双方向、多次触发、Halt、Quick stop、故障与限位分别验收。

### 12.3 PV：Profile Velocity，模式 3

- PV-01（M）：驱动器对 0x60FF 目标速度按选定轮廓加减速。
- PV-02（M）：零速保持／撤销励磁、反转、最大速度和负载能力公开。
- PV-03（M）：速度反馈定义、允许误差、稳定时间与过载条件可测。
- PV-04（M）：速度请求超限时返回或标记限制状态；不得整数截断后变成反方向。
- PV-05（M）：停止、故障、总线中断与重新使能不会恢复旧的非零速度。

### 12.4 CSP：Cyclic Synchronous Position，模式 8

CSP 由主站持续提供周期目标位置。主站一般负责轨迹规划，驱动器负责规定时刻采样、位置跟随和本地限幅。不得使用 PP 的 bit4 逐圈触发方式替代周期目标。

- CSP-01（M）：在选定 SM／SYNC0 时刻锁存一致目标，与周期号及命令有效性绑定。
- CSP-02（M）：目标斜坡的速度由相邻位置差和周期决定；不通过改变 PLC 任务周期作为日常调速手段。
- CSP-03（M）：连续恒速、五次平滑轨迹、驻留、换向、目标突变、暂停恢复均无未定义行为。
- CSP-04（M）：缺失／迟到命令、重复目标值、应用未消费、PDI 读失败分别定义处理，不能把这些情况混为同一种计数。
- CSP-05（M）：公开跟随滤波、插补、加减速限制和饱和造成的时延／误差；主站送出的轨迹不能被未知滤波随意改变。
- CSP-06（M）：当前约 20 ms 跟随环节仅是现有实现方案，不能据此宣称严格零滞后同步。产品版需验证或改进插补／控制方式，并规定动态跟随误差预算。
- CSP-07（M）：当前开环 0x6064 的变化只证明相位推进。验收一圈必须使用外部机械标记、编码器或测角设备，并结合负载工况。
- CSP-08（M）：运动中失联的本地反应必须独立存在；PLC 发控制字 0 不能保证失联驱动器收到该命令。
- CSP-09（M）：连续累计位置接近 DINT 边界时按设计停机／换坐标；如需要长期连续旋转，设计明确的坐标重基准或正式扩展协议，不能让有符号数溢出。

计算示例（仅用于理解单位）：1000 计数／圈、2 ms 周期、60 rpm 时平均每周期增加 2 计数；非整数增量需要保留余数，不能每周期截断造成累计误差。该例不代表所有细分、负载和机械都能精确运行。

“转一圈、停 0.5 秒、再转一圈”必须分为轨迹进行、等待到位、连续停稳确认、驻留四个阶段；驻留时间从约定的到位／停稳条件成立后开始，而不是从目标刚发送完便开始。

### 12.5 CSV：Cyclic Synchronous Velocity，模式 9

- CSV-01（M）：每周期接收速度目标并在规定时刻消费；目标为零也是有效新命令。
- CSV-02（M）：本地加速度限制与滤波必须公开。CSV 与 PV 不应只改模式显示而没有清晰的周期语义。
- CSV-03（M）：正负速度、低速量化、零速、换向、阶跃、斜坡和极限速度均需验证。
- CSV-04（M）：通信中断不能无限保持最后一个非零速度；采用本地批准的失联停止策略。
- CSV-05（M）：0x606C 的单位、过滤与刷新周期明确；若来自励磁推进而非编码器，文档必须标注。

### 12.6 HM：Homing，模式 6（当前待实现）

需要机械原点的产品不能用上电直接清零代替完整回零。

1. 定义支持的方法及所需原点开关、限位、编码器 Z 相等硬件；只声明实际具备的方法。
2. 定义 0x6098 方法、0x6099 速度、0x609A 加速度、0x607C 偏移及相关输入／状态对象的适用范围。
3. 实现寻原点、减速、反向脱离、低速接近、锁存位置、应用偏移、完成等适用状态；不是每一种方法都需要所有步骤。
4. 实现方向、开关极性、去抖、最大寻零距离、超时、初始就在开关上、开关粘连与断线的处理。
5. 完成、错误和中断采用模式规定的状态位；Halt、Quick stop、故障、失联可中止回零。
6. 定义每次上电是否必须回零、何时回零状态失效、停机／参数改变是否需要重新回零。
7. 若提供“当前位置设为原点”，明确这只是坐标设定，不能证明找到了机械基准。
8. 机械到位和重复性用外部仪器验证，覆盖不同接近方向、速度、温度和负载。

### 12.7 PT／CST 及闭环扩展（当前不声明）

若后续支持，需增加真实电流采样、校准、受控电流环、转矩常数／估计模型、量纲、限幅、热模型、反馈有效性与相应状态语义。输出电流设置不是自动等于精确轴转矩；开环相位计数不是闭环位置控制。

## 13. DC 同步与多轴运动

### 13.1 单轴同步

- SYNC-01（M）：区分 PLC／NC 任务周期、EtherCAT SyncUnit 周期、SYNC0 周期、电机 16 kHz 周期，记录关联和相位关系。
- SYNC-02（M）：0x1C32／0x1C33 的周期、支持模式、最小周期、计算／复制时间与诊断语义真实；不能长期填零或固定数值掩盖未测量的能力。
- SYNC-03（M）：在支持的最短周期、最长周期和边界偏移下验证 PDO 到达、SYNC0 采样、应用计算和反馈发布顺序。
- SYNC-04（M）：不任意修改 Shift Time 或增加容错阈值来消除错误。任何调参都要对应测量、允许窗口和版本化记录。
- SYNC-05（M）：SYNC0 丢失、迟到、过快、SM 事件遗漏和真正超周期能正确识别，不把合法晚到的首次事件当作重复事件。
- SYNC-06（M）：同步故障快照不能在自动回到 OP 后被覆盖；恢复后保持无自动运动的策略。
- SYNC-07（M）：SM 模式与 DC 模式分别验收；SM 稳定不能证明 DC 已合格，DC 勾选成功也不能证明应用真正按 SYNC0 消费数据。

单位换算必须在配置检查中明确：当前常用 2 ms 等于 2000 μs，也等于 2000000 ns。TwinCAT 的 SYNC0 配置框与同步对象的单位可能不同，不得把同一个整数直接复制过去。0x60C2 的时间值及指数按其定义换算成时间；它的配置、主站周期和固件实际选择的时间源必须一致，不能仅因对象可读写就假定参与了控制。

### 13.2 两台驱动器同时正转一圈、反转一圈

本产品仍是单轴驱动器；双轴应用由主站协调两台设备，不能为每台设备用独立人工点击来宣称同步。

1. 两轴使用一致的 SyncUnit／DC 策略与已验证周期；主站在同一任务、同一周期形成两轴命令。
2. 分别校验两轴方向、每圈计数、齿轮比和起点；不要求两轴绝对坐标数值相同。
3. 只有两轴均已就绪、反馈有效且起始条件满足时，才允许同步启动。
4. 用共同轨迹进度生成目标：轴 A 为 A0 + NA×进度，轴 B 为 B0 + NB×进度；反向阶段返回各自起点。
5. 等待两轴均达到约定到位条件再开始共同驻留；规定两轴不同步或其中一轴未到位的超时策略。
6. 一轴故障时触发组级处理；另一轴如何停止由机械耦合和风险决定。不能假定仅在 PLC 发一次停止字即可覆盖失联轴。
7. 验收同时记录 PDO 周期号、目标、内部计数和独立测得的轴位置，计算时间偏差与轨迹误差。
8. 两轴内部各有约 20 ms 平滑不代表两轴实际滞后完全相同；不同负载、限幅和机械失步必须单独验证。

## 14. 参数、标定与非易失存储

### 14.1 参数分类

| 类别 | 典型内容 | 管理方式 |
| --- | --- | --- |
| 生产身份 | 序列号、硬件版本、校准版本 | 受控写入，出厂默认恢复不应误删 |
| 电机／电流参数 | 电流限值、电机类型、校准、降额 | 权限、范围和硬件依赖校验 |
| 运动参数 | 分辨率、齿轮比、速度／加速度、限位 | 按允许状态修改并原子提交 |
| 通信参数 | PDO 方案、同步参数、部分超时 | 与 ESI、重启和主站 Startup 流程配合 |
| 运行命令 | 控制字、瞬时目标、Run 请求 | 默认不持久化，不允许上电恢复运动请求 |
| 诊断 | 首错、总计数、运行时间 | 限速记录，区分 RAM 与持久化生命周期 |

### 14.2 存储要求

- PARAM-01（M）：定义每个参数的 RAM 值、已保存值、生效值；保存成功不能只代表请求入队。
- PARAM-02（M）：采用有版本的记录：magic、格式版本、长度、序号、有效标志、载荷和 CRC；CRC 只能检测意外损坏，不代替防篡改认证。
- PARAM-03（M）：采用适合介质容量和寿命的双槽／日志／其他原子提交方案；任何擦写阶段掉电都至少保留一份可恢复数据。
- PARAM-04（M）：先校验和写入完整新记录，验证成功后再使其有效；不能先破坏唯一旧副本。
- PARAM-05（M）：定义写入寿命、限速、合并、磨损管理和空间耗尽处理。不得每个 PDO 周期存目标，也不能每次错误计数变化就写 EEPROM。
- PARAM-06（M）：保存操作禁止危及实时环；如擦写会阻塞取指，应在禁止驱动的维护状态执行，或采用经测量验证的实现。
- PARAM-07（M）：参数版本升级可迁移，不可迁移时使用明确的默认／禁止运行策略并报告；不能静默误解旧格式。
- PARAM-08（M）：损坏、校验失败、范围非法时禁止使用危险参数启动，保留错误与原因。
- PARAM-09（M）：若提供 0x1010／0x1011，按选定标准实现保存／恢复命令、签名、权限、子索引和结果；存在 SaveFunc.c 不等于这些对象已经支持。
- PARAM-10（M）：与主站 Startup 参数优先级协调：上电读取的已保存值可能被 Startup 覆盖，说明书必须解释最终值由谁决定。
- PARAM-11（M）：默认恢复区分用户参数、校准参数和身份信息；恢复前必须禁止驱动，恢复后不自动使能。
- PARAM-12（M）：保存电气相位／累计计数也不等于断电绝对位置恢复；没有绝对传感器时，上电坐标有效性必须明确。

当前 EEPROM 空间与布局需要单独核算；不要把 SII EEPROM、应用参数 EEPROM 和 MCU Flash 当作同一块存储。

## 15. 故障检测、保护和错误上报

### 15.1 故障分层

区分硬件紧急关断、驱动故障、通信故障、参数错误、警告和主站主动停止。它们可以同时发生，但必须保留首因及后续结果，不能全都显示为“电机错误”。

| 类别 | 检测依据 | 典型响应要求 | 复位条件 |
| --- | --- | --- | --- |
| 严重过流／功率级故障 | 独立比较器／驱动芯片故障与校准采样 | 按硬件设计立即抑制危险输出，随后软件锁存 | 真实原因消除、稳定时间及人工请求 |
| 母线过压／欠压 | 校准电压测量与供电状态 | 根据能量、制动能力和风险决定受控停机或关断 | 电压回到带迟滞的有效区间 |
| 过温／传感器故障 | 功率级／环境温度、断线／短路诊断 | 警告、降额、故障等级有明确阈值 | 温度与传感器状态恢复 |
| 电机缺相／接线异常 | 经验证的电流或其他诊断方案 | 禁止继续危险驱动并标注检测限制 | 检查接线并重新验证 |
| 编码器异常 | 仅适用于已配置编码器的型号 | 禁止依赖无效反馈继续闭环 | 信号与位置可信度恢复 |
| 机械跟随误差／堵转 | 编码器或经过验证的实际检测能力 | 限时检测、停止、锁存 | 原因消除并重新建立位置 |
| 软件／硬件限位 | 坐标比较及实体输入 | 明确触发方向、制动距离和允许脱离动作 | 按受控规则脱离，不屏蔽全部保护 |
| EtherCAT 数据失效 | 从站自身看门狗／PDO 时序；主站 WcState | 本地失联响应 + 主站组级处理 | 通信稳定且重新确认启动 |
| DC 同步异常 | SYNC0／SM 计数与窗口 | 按声明协议行为退态并执行输出策略 | 同步恢复并重新使能 |
| SQI／存储／软件异常 | 返回错误、超时、CRC、看门狗、异常寄存器 | 阻止使用无效数据，进入定义状态 | 可恢复性评估与受控复位 |

矩阵中的检测是产品需求，不表示当前全部具备。特别是当前一个 VFO 低有效信号不能区分所有母线、温度和缺相故障；必须依据硬件可观测量建立分类。

### 15.2 必须设计的故障属性

- FAULT-01（M）：每种故障有编号、名称、物理含义、来源、严重度、阈值、去抖、迟滞和最大检测时间。
- FAULT-02（M）：区分检测时间、软件反应时间、输出关断时间和机械停止时间，不以清标志时间代替安全动作时间。
- FAULT-03（M）：第一故障锁存不被后续掉 OP、控制字清零等后果覆盖；同时保存后续事件环形日志。
- FAULT-04（M）：标准错误码、0x1001 类别位、状态字 Fault/Warning、厂商子码与说明书一致；参考其他品牌手册不代表可以照搬其私有语义。
- FAULT-05（M）：复位判据根据具体故障检查，不能所有类别只检查 VFO 已恢复。清除诊断、清除故障和重新使能是三个独立动作。
- FAULT-06（M）：故障存在时持续写 Fault Reset 不能重新打开危险输出；上电、重新 OP 或 PLC 下载不能绕开故障条件。
- FAULT-07（M）：异步 EMCY 若纳入本版，必须实现事件触发、队列、满队列策略和恢复消息等所选规范行为；当前 EMERGENCY_SUPPORTED=0 需作为未实现项管理。
- FAULT-08（M）：历史记录不写成纯字符串；保存机器可分析的编号、时间、会话、状态、参数和版本。
- FAULT-09（M）：本地失联策略不能只依赖主站 WcState。WcState 是主站诊断映像，从站要依据自己能够检测的有效 PDO、SM 看门狗、同步和本地健康状态行动。
- FAULT-10（M）：不会因为关闭报警、提高阈值、伪造到位／同步计数而获得“长期不停机”的验收通过。

## 16. 诊断记录与自动停转问题的闭环

### 16.1 诊断记录最低字段

| 类别 | 建议字段 |
| --- | --- |
| 版本与会话 | 固件 Git 哈希、ESI Revision、硬件／参数版本、boot_session_id、reset_cause |
| 时间与事件 | 单调时间戳、周期号、事件序号、首因编号、后果编号、有效标志 |
| EtherCAT | AL 状态／状态码、DC／SM 模式、期望周期、最后有效 PDO 时间和序号 |
| CiA402 | 状态、请求／显示模式、控制字、状态字、错误码 |
| 运动 | 目标位置／速度、内部计数、真实编码器值（若有）、限幅与停止控制器状态 |
| 时序 | ISR 最大时长、入口延迟、超周期数、SQI 最大事务时间／超时数 |
| 硬件 | 电压、电流、温度、输入状态、故障引脚与各自有效性 |
| 主站 | WcState、InfoData.State、FrmXWcState、Lost Frames、Tx/Rx、CRC 的基线和增量 |

不要求所有字段全塞进默认 PDO。高频必需量可用 PDO，完整快照通过低频 SDO／维护接口读取；日志读取也需要资源与频率上限。

### 16.2 生命周期与实现规则

- DIAG-01（M）：分别维护启动阶段累计、已使能运行累计、连续异常周期、异常事件次数。不能把异常周期数叫作“掉线次数”。
- DIAG-02（M）：快照先填内容、最后提交有效标志／序号；读者能判断快照是否一致。多上下文写日志需有明确仲裁。
- DIAG-03（M）：首次故障记录默认保留到人工确认；断电是否保留必须公开。持久化使用延后、限速与介质寿命策略。
- DIAG-04（M）：保留启动原因并区分人工复位、看门狗、欠压／上电等芯片能可靠提供的原因；不能把所有复位都叫软件异常。
- DIAG-05（M）：在不中断实时运行的情况下获取日志；调试器暂停 MCU 造成的故障必须标注为人为注入。
- DIAG-06（M）：硬件、MCU 和主站时间未同步时，记录关联事件和误差范围，不将相近截图时间当作严格因果顺序。

### 16.3 本工程 nStopReason 的解释

当前 SmoothRepeat 使用可组合位掩码：1=WcState 无效；2=非 OP；4=Fault；8=已就绪后失去就绪条件；16=到位超时；32=位置范围；64=配置错误；128=外部取消 Enable 的操作记录；256=外部取消 Run 的操作记录；512=使能超时。

nStopReason=1 不代表“只丢了一帧”，也不等于某个从站硬件错误码。当前示例会在运行使能期间观察到一个异常周期后锁存停机，这是应用的保守策略，不是 EtherCAT 对所有应用规定的唯一容错次数。

如未来需要容许短暂异常，必须另行定义最大数据年龄、单次／连续异常阈值、保持或停止策略、从站本地监督、风险边界和验收场景。不得直接把判断删掉、阈值设无限大或故障恢复后自动重启。

WcState=1 时输入可能仍显示最后一个有效值；InfoData 不是同一实时周期的完整证据。因此“快照状态字看起来使能”和“当前又回 OP”不排除此前通信故障。[WcState 说明](https://infosys.beckhoff.com/content/1033/b110_ethercat_optioninterface/1984417163.html) [附加诊断说明](https://infosys.beckhoff.com/content/1033/tcsystemmanager/1089009035.html)

### 16.4 复现实验流程

1. 记录固件、PLC、ESI、接线、网卡、供电、负载、周期和本次所有人工操作；保存旧记录。
2. 稳定 OP、失能停转、无故障时清理本次 PLC 诊断，记录主站计数基线；启动与运行阶段分开统计。
3. 用同一配置依次执行 OP 未使能、使能静止、低速运动、目标工况和邮箱压力测试，不同时更改多个因素。
4. 自行停止后不重启、不退出 OP、不暂停 MCU，先读取首错快照、主站和固件计数增量。
5. Master Lost Frames／Tx/Rx 的增加用于定位收发路径；CRC 增加用于调查受损帧和物理链路。非零累计值不能直接证明当前事件原因。[主站 Online 说明](https://infosys.beckhoff.com/content/1033/tc3_io_intro/1446518411.html)
6. 若仅 WcState 异常，结合帧／命令级状态、AL 事件、看门狗和 PDI 记录继续调查；不同从站可能共享同一报文诊断。
7. 采用相同主站、网口、电缆、周期和负载进行对照；成品驱动器不停与自研驱动器停，不自动证明某一特定代码行出错，双方恢复策略可能不同。
8. 每个假设一次只改变一个因素，保留反证；修复需有复现前后证据与回归。

## 17. 固件升级、维护与软件资产管理

### 17.1 升级能力

当前 FoE／Bootstrap 关闭。首版可以使用受控维护接口升级，但必须说明现场如何升级、失败如何恢复，以及客户是否需要开盖或专用工具；不能把开发阶段 SWD 烧录自动视为完整现场升级方案。

- FW-01（M）：发布包有产品型号、硬件兼容范围、固件版本、参数格式版本、长度及完整性校验。
- FW-02（M）：进入升级前禁止驱动并确认输出状态；主站保留的非零命令不能在升级完成后自动恢复运动。
- FW-03（M）：拒绝错误型号、损坏、截断、重复及不兼容镜像，定义拒绝后的行为。
- FW-04（M）：升级任意阶段掉电后，仍能启动有效版本或进入可靠恢复入口；具体采用双区、独立 Bootloader 或其他经容量分析的方案。
- FW-05（M）：参数与固件升级兼容；失败回退不能留下新固件参数被旧固件误读的组合。
- FW-06（M）：记录升级原因、前后版本、结果和恢复路径，不以通信已收到文件就宣布升级成功。
- FW-07（M）：按威胁模型设计真实性验证与维护权限；CRC 防意外损坏，不保证镜像来自授权发布者。
- FW-08（M）：如增加 FoE，除文件传输外，还要完成写入调度、镜像校验、Boot 状态、复位、回滚与输出安全测试。
- FW-09（M）：调试口读保护、生产权限与返修能力统一设计；不能在未演练恢复前启用不可逆配置。

### 17.2 交付与工程管理

- 发布包同时包含 ESI、固件、校验值、版本说明、参数说明、错误码表、接线说明和可重复建立的主站示例。
- Git 只保存许可允许的内容；SSC 源码、闭源电机库和第三方 SDK 的再分发范围需确认，不能因为仓库可推送就默认允许公开。
- 不把密钥、令牌、私有证书或个人凭据写入源码／示例。
- 维护组件清单：版本、来源、许可、修改、工具链和已知问题；可作为软件物料清单基础。
- 修改默认 PDO、模式支持位、单位或参数格式必须提供兼容性迁移说明。
- PLC 示例应给出新建工程、声明区／执行区粘贴位置、映射、周期、启动、正常停止、异常取证和复位步骤；不同版本使用明确名称，不要求用户猜测哪个才是最新版。

## 18. 硬件、电气、机械与中国市场合规准备

### 18.1 硬件设计不能由协议软件代替

- HW-01（M）：功率级在上电、MCU 复位、未配置 GPIO、时钟异常和调试下载阶段具有定义的禁止状态。
- HW-02（M）：电流采样、偏置、增益、ADC 饱和、采样失效及输入开短路有设计与校准依据。
- HW-03（M）：功率保护的硬件关断路径、软件锁存和实际输出波形均验证；软件反应不能替代半导体所需的快速保护。
- HW-04（M）：电源欠压、掉电斜率、上电次序、看门狗和棕断复位处理一致；禁止不完整初始化后开启 PWM。
- HW-05（M）：EtherCAT PHY、时钟、磁性器件、连接器、屏蔽、布线与接地按器件要求设计并验证，检查功率 PWM 对通信的耦合。
- HW-06（M）：板温、电机温度（若测量）、散热、堵转／保持电流发热与最高环境温度纳入降额设计。
- HW-07（M）：断电、输出关断和通信失效时，水平／垂直负载、惯性和制动器的行为需单独评估；失去励磁可能失去保持力。
- HW-08（M）：明确禁止带电插拔电机线等危险维护操作；危险故障注入在合格试验工装、限能条件和有资质人员监督下进行。
- HW-09（M）：没有真实测量或经过验证的估算时，不能宣传堵转检测、缺相检测、过温检测或精确转矩。

### 18.2 合规路线

当前仅确认销售区域为中国，额定输入电压、输出电流、使用环境和安装形式尚未冻结，因此本文不能判定具体强制认证目录、试验等级或所有适用标准。

在设计冻结前，应由熟悉驱动产品的检测机构／合规人员建立标准适用性表，至少评估以下方向：

| 方向 | 需要评估的范围 | 输出文件 |
| --- | --- | --- |
| 电气安全 | 驱动系统安全要求、绝缘、接地、温升、端子与保护 | 适用标准版本、试验方案、风险关闭记录 |
| EMC | 电驱动产品的发射与抗扰度；端口、环境、线缆和安装类别 | 测试等级、判据、配置、实验室结果 |
| 环境可靠性 | 温湿度、振动、机械冲击、储存与运输等适用项目 | 试验计划及失效处理 |
| 产品标识与说明 | 额定值、警示、接线、降额、维护、追溯 | 标签、说明书和安装条件 |
| 市场准入 | 根据产品归类核对适用法规、目录与客户要求 | 书面适用性判断，不凭经验省略 |
| EtherCAT 互操作／符合性 | 所选 ETG 规范、测试工具、申报与商标使用条件 | 版本化检查清单、CTT／实验室结果 |

可从 IEC 61800 系列相关安全／EMC／通信要求及相应国内标准体系着手评估，但不能把系列号当作本产品已经适用或已经通过的结论。国内标准的现行、被代替和实施状态应逐项查证。[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/index)

内部测试报告、第三方实验室报告、EtherCAT 符合性测试和功能安全认证是不同证据，不能相互替代。当前不宣称 STO；未来若加入 STO，须独立立项，不能通过增加一个断使能引脚或控制字就获得该声明。

## 19. 生产、出厂与售后要求

### 20.4 长时间与样本覆盖建议

1. 开发自测：先低速空载 20 圈，再超过历史常见停机时长，之后进行至少 8 小时代表工况测试。
2. 工程验证：建议至少 3 台样机覆盖不少于 2 个装配／物料批次；每种主要运动／同步组合做 72 小时测试。
3. 发布候选：建议对最高风险且在声明范围内的组合做 168 小时测试，覆盖邮箱读写与通信恢复场景；时长、样本与组合可在评审中提高或有依据地调整。
4. 温度、供电、线缆、负载与分辨率采用覆盖矩阵；不能只选最容易通过的一套配置。
5. 非注入条件下，任何未解释复位、非预期运动、越界、静默数据损坏或重复性异常都判失败。普通停机也必须有可解释、符合规格的原因。
6. 计划内边界限制停止必须与随机停机区分；连续运行接近位置范围时应按预定方案重基准，不能为完成 168 小时而关闭范围保护。
7. 零故障测试结果不是“故障率为零”或无限寿命证明；不能直接从单台短时运行推导商用可靠性指标。

### 20.5 当前回归资产的使用

现有同步回放、内部相位 ARM 测试、PLC 示例测试应接入发布回归；执行前确认依赖、固件产物与源码版本一致。历史文档的 22 项同步回放或 ARM 测试通过，只证明当时记录的测试范围，不能证明电机不会丢步或本次故障已经修好。

建议新增：停止控制器单测、SQI 故障传播测试、参数掉电恢复测试、模式能力表一致性测试、ESI/OD/PDO 自动核对、首错快照一致性、复位原因与非法反馈测试。
